Serve React Frontend from FastAPI at /dashboard                                                           
  
 Context

 The frontend (React + Vite) and backend (FastAPI) are completely disconnected — the frontend has zero API 
  calls and runs as a standalone Vite dev server. The goal is to have FastAPI serve the built React app at 
  GET /dashboard, so the entire app runs from a single server at http://127.0.0.1:8000.

 The existing health-check at GET / stays unchanged. No API data-fetching wiring or dock functionality is  
 needed yet.

 Plan

 1. Update Vite config — frontend/vite.config.js

 Add base: '/dashboard/' so the production build references assets at /dashboard/assets/... instead of     
 /assets/...:

 export default defineConfig({
   base: '/dashboard/',
   plugins: [react()],
   resolve: {
     alias: {
       '@': path.resolve(__dirname, './src'),
     },
   },
 })

 This only affects npm run build output. npm run dev still works normally.

 2. Add dashboard route and static mount — backend/main.py

 Add these imports:
 from fastapi.staticfiles import StaticFiles
 from fastapi.responses import FileResponse

 Add the route (before any app.mount calls):
 @app.get("/dashboard")
 async def dashboard():
     """Serve the React frontend's built index.html."""
     return FileResponse(
         path.join("frontend", "dist", "index.html"),
         media_type="text/html"
     )

 Mount the built static files directory at the end of main.py (mounts must come after route definitions):  
 app.mount("/dashboard", StaticFiles(directory=path.join("frontend", "dist")), name="dashboard-static")    

 How this works:
 - GET /dashboard → explicit route wins → serves index.html
 - GET /dashboard/assets/index-abc123.js → mount handles it → serves the JS bundle
 - GET /dashboard/favicon.svg → mount handles it → serves the favicon
 - All existing API routes (/, /track, /news) remain unchanged

 3. Add aiofiles dependency — backend/requirements.txt

 Append aiofiles — Starlette's FileResponse requires it for async file serving.

 4. Build the frontend

 cd frontend && npm run build

 This produces frontend/dist/ with the bundled app. This step must be run before /dashboard will work.

 Important Notes

 - Path resolution: main.py uses path.join("frontend", "dist", ...) which resolves relative to CWD. The    
 server must be started from the repo root (python backend/main.py from unihack-hackathon-submission/) or  
 the path adjusted accordingly. Need to verify current startup CWD.
 - Dev workflow unchanged: npm run dev still serves the frontend at :5173 for development. The /dashboard  
 route is for serving the production build only.
 - No CORS needed: Since the frontend is served from the same origin (:8000), no CORS configuration is     
 required for future API calls.
